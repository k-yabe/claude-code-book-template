# エージェント一覧

> 各エージェントは「役割を持った AI 社員」です。タスクの内容に応じて自動的に適切なエージェントに割り振られます。

---

## 組織図

```
                    ┌─────────────────────┐
                    │   あなた（オーナー）  │
                    └──────────┬──────────┘
                               │
              ┌────────────────┼────────────────┐
              │                │                │
    ┌─────────▼──────┐ ┌───────▼──────┐ ┌──────▼──────────┐
    │  エンジニアリング  │ │ コンテンツ   │ │   ビジネス      │
    │     チーム      │ │   チーム     │ │    チーム       │
    └────────────────┘ └─────────────┘ └─────────────────┘
    tech-lead           content-director  marketing-director
    frontend-engineer   brand-voice       business-strategist
    backend-engineer    root-cause        partnership-manager
    qa-engineer         anti-ai-slop      legal-review
                               │
                    ┌──────────▼──────────┐
                    │   インフラ運用チーム   │
                    │  task-dispatcher    │
                    │  local-support      │
                    └─────────────────────┘
```

## エンジニアリングチーム

### 🔧 tech-lead（テックリード）
- **役割**: 技術的な設計・実装方針・コードレビュー
- **使うモデル**: Haiku（Web検索あり）
- **こんなタスクを振る**: 「APIの設計を考えて」「このエラーの原因を調べて」
- **自動割り当てキーワード**: コード、バグ、実装、エラー、テスト、デプロイ、API

### 🎨 frontend-engineer（フロントエンドエンジニア）
- **役割**: UI/HTML/CSS/JavaScript の実装
- **使うモデル**: Haiku
- **こんなタスクを振る**: 「ボタンのデザインを修正して」「レイアウトを整えて」
- **自動割り当てキーワード**: UI、フロントエンド、デザイン、レイアウト、CSS

### ⚙️ backend-engineer（バックエンドエンジニア）
- **役割**: API/データベース/インフラの設計・実装
- **使うモデル**: Haiku
- **こんなタスクを振る**: 「DBのスキーマを設計して」「サーバーの処理を最適化して」
- **自動割り当てキーワード**: バックエンド、DB、データベース、サーバー、インフラ

### 🧪 qa-engineer（QAエンジニア）
- **役割**: 品質チェック・テスト・検証
- **使うモデル**: Haiku
- **こんなタスクを振る**: 「この機能のテストケースを作って」「品質チェックして」
- **自動割り当てキーワード**: 品質、QA、検証、チェック

## コンテンツチーム

### 📝 content-director（コンテンツディレクター）
- **役割**: 記事・動画台本・LP・メール・SNS投稿などの制作
- **使うモデル**: Haiku（Web検索あり）
- **こんなタスクを振る**: 「YouTube台本を書いて」「ブログ記事を作って」
- **自動割り当てキーワード**: 記事、ブログ、動画、スクリプト、台本、コンテンツ

### 🎙️ brand-voice（ブランドボイス）
- **役割**: ブランドのトーン・言葉遣いのチェック
- **使うモデル**: Haiku
- **こんなタスクを振る**: 「このテキストのトーンがブランドに合っているか確認して」

### 🔍 root-cause（ルートコーズ）
- **役割**: 本質・深さのチェック（表面的でない分析）
- **使うモデル**: Haiku
- **こんなタスクを振る**: 「この問題の本質的な原因を掘り下げて」

### 🚫 anti-ai-slop（アンチAIスロップ）
- **役割**: AI らしい（薄い・ありきたりな）表現の除去
- **使うモデル**: Haiku
- **こんなタスクを振る**: 「このテキストのAIっぽい言い回しを直して」

---

## ビジネスチーム

### 📣 marketing-director（マーケティングディレクター）
- **役割**: マーケティング戦略・施策・コピーライティング
- **使うモデル**: Haiku（Web検索あり）
- **こんなタスクを振る**: 「このサービスのSNS施策を考えて」「集客コピーを書いて」
- **自動割り当てキーワード**: マーケ、マーケティング、宣伝、SNS、プロモ

### 💼 business-strategist（ビジネスストラテジスト）
- **役割**: 事業戦略・意思決定の分析（重要案件）
- **使うモデル**: **Sonnet**（高性能モデル。戦略的判断に使用）
- **こんなタスクを振る**: 「この新規事業の可能性を分析して」「収益モデルを考えて」
- **自動割り当てキーワード**: 戦略、ビジネス、事業、収益、方針

### 🤝 partnership-manager（パートナーシップマネージャー）
- **役割**: 案件・提携・コラボの管理
- **使うモデル**: Haiku
- **こんなタスクを振る**: 「この提携の条件を整理して」「コラボ候補をリストアップして」
- **自動割り当てキーワード**: 案件、パートナー、コラボ、提携

### ⚖️ legal-review（リーガルレビュー）
- **役割**: 契約書・利用規約の確認（一次チェック）
- **使うモデル**: Haiku（Web検索あり）
- **こんなタスクを振る**: 「この契約書の注意点を教えて」「規約の不明点を確認して」
- **自動割り当てキーワード**: 契約、法的、リーガル、規約

> ⚠️ legal-review は一次確認のみです。重要な法的判断は必ず専門家（弁護士）に確認してください。

## インフラ運用チーム

### 📬 task-dispatcher（タスクディスパッチャー）
- **役割**: inbox 監視・タスク自動生成・担当エージェントへの割り振り
- **使うモデル**: Haiku
- **これは手動で使うものではなく、システムが自動で動かす**

### 🖥️ local-support（ローカルサポート）
- **役割**: ローカルで動くメンテナンス処理（将来拡張用）
- **現在は未使用**

## エージェントへの割り振りルール

タスクのテキストにキーワードが含まれると、自動的に担当が決まります。

```
メモの内容
    │
    ▼
キーワード判定
    │
    ├── 「コード」「API」「バグ」 ─────→ tech-lead
    ├── 「UI」「CSS」「フロント」 ──────→ frontend-engineer
    ├── 「DB」「サーバー」「インフラ」 ──→ backend-engineer
    ├── 「台本」「記事」「コンテンツ」 ──→ content-director
    ├── 「マーケ」「SNS」「プロモ」 ────→ marketing-director
    ├── 「戦略」「ビジネス」「事業」 ───→ business-strategist
    ├── 「契約」「規約」「リーガル」 ───→ legal-review
    └── （該当なし） ────────────────→ tech-lead（デフォルト）
```

## Web検索が使えるエージェント

以下のエージェントは、最新情報が必要なタスクで自動的に Web 検索を行います：

| エージェント | 主な用途 |
|-------------|---------|
| content-director | 最新トレンド・事例調査 |
| marketing-director | 競合・市場調査 |
| business-strategist | 業界動向・事業分析 |
| tech-lead | 最新技術・ライブラリ調査 |
| legal-review | 法改正・規制調査 |
