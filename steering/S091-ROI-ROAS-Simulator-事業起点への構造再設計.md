## 目的

「営業資料をインポートしても、どの事業（コンサル／ソリューション／アカデミー）で試算しているか分からない。成約率・客単価・粗利率・LTV は事業で激変するのに、資料だけで判断するのは構造上の欠陥」というユーザー指摘に対応。経済性は事業が持ち、資料・手入力は予算・流入を供給するだけ、という正しい構造に作り直す。事業はAI推定せず、ユーザーが3択から選ぶ（確実・手間も小さい）。

---

## スコープ

### やること
- [x] 導線を3ステップに再設計（STEP1 事業 → STEP2 予算・流入［手入力 or 資料］→ STEP3 判定）。はじめ方ガイドを刷新し DOM もこの順に並べ替え
- [x] 事業選択を起点（`svc-step`・STEPバッジ）に、`import-step` を STEP2 として配置
- [x] `applyExtracted` は予算・流入のみ読み取り、事業選択済みなら経済性を上書きしない
- [x] `econAnchored`／`isAnchored()` で判定をゲート：事業未選択のうちは KPI・判定を「—」にし、verdict は「STEP1 事業を選んでください」
- [x] 基準バー文言を新構造に合わせて更新
- [x] 回帰テスト更新（事業ゲート・新ガイド・新メッセージ）／WHAT'S NEW・オンボーディング・docs 更新

### やらないこと（スコープ外）
- AIによる事業の自動推定（ユーザーが選ぶ方針）
- 全事業の自動一括比較（必要なら手動で事業を切り替えて比較）

---

## 完了条件

- [x] 事業を選ぶまで黒字/赤字・ROAS/ROI が出ず、選ぶと即座にその経済性で試算される
- [x] 資料インポートは予算・流入のみを供給し、選択中事業の経済性を壊さない
- [x] 「いま何の事業で試算しているか」が常に分かる
- [x] `npm run test:roi` 全 pass（114 アサーション）
