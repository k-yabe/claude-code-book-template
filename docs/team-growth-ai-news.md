## 1. ざっくり何を作ったか

**AKKODiS マーケティングチーム向けの AI × マーケティング最重要ニュース配信アプリ**
URL: https://kunito-yabe.vercel.app/apps/ai-news/

毎朝 8:00 JST に自動更新され、「何が起きた？なぜ重要？何をすべき？」の 3W を 5 分で把握できるダッシュボード。音声ダイジェスト、PWA オフライン対応、Slack 共有、印刷用 PDF 書き出しまで対応。

## 2. 具体的にやったこと（14 バッチ）

### データパイプライン
1. **20+ 媒体横断 RSS 収集**（MarkeZine / DIGIDAY / ITmedia / 日経クロステック etc. + Qiita/Zenn/note は少量）
2. **Claude Haiku 4.5 で要約 + マーケ視点スコアリング**（なぜ重要か / 何をすべきか）
3. **はてなブックマーク数でバズ判定**（超新着 >=1 / 通常 >=3 / 主要 >=10）
4. **UGC (Qiita/Zenn/note) を主要枠から除外**、ツール系は例外的に救済
5. **「はじめに/概要/TL;DR」等の boilerplate プレフィクス自動剥がし**
6. **URL 到達性チェック**（HEAD→GET で 200-399 のみ採用 = リンク切れゼロ保証）

### 音声ダイジェスト
7. **毎朝 GitHub Actions で事前生成**：Claude Haiku 台本 → OpenAI `gpt-4o-mini-tts / nova` → MP3 → リポにコミット
8. **クリック即再生**（Vercel 静的配信、待ち時間ゼロ）。Web Speech API に 2段フォールバック
9. **NHK アナウンサー風の読み上げ指示**（抑揚・ポーズ・カタカナ読み）を英語 instructions で細かく制御

### UX
10. タグ・ソース名クリックで絞り込み、FYI ツールバー sticky、読了時間「⏱ N分」、「📰 N媒体報道」バッジ
11. ★お気に入り / 🌙 夜間読書モード / 📤 共有 / 週間読書統計 ミニバー / 🛠 ツール活用バッジ
12. 「もっと見る」で初期10件→全件展開、スクロール進捗バー、連読ストリーク
13. OGP / Twitter Card / PWA Service Worker / 印刷用 stylesheet

### 品質担保
14. **Playwright 自動テスト 18 件**（基本表示 / インタラクション / データ構造 / アクセシビリティ / PWA / SEO）を CI 化

## 3. チームへの学びシェア（7 つ）

### 🎯 学び 1: スペック駆動開発 × Claude Code の相性
- `CLAUDE.md` に「1ファイルずつ実装」「WHAT'S NEW 必須更新」「ブランドルール」を書いておくと、AI が勝手に遵守してくれる
- `design-rules.md` のような機械可読ルールを置くと、実装中にリアルタイムで色違反を検出・修正できた
- **テンプレ化可能**：今後のアプリにもこの仕組みをコピーすればブランド遵守が自動化される

### 🔄 学び 2: フィードバックからの反復が最速
- 初期実装 → ユーザー（自分）が使って違和感 → 即修正、のループを 14 バッチ回した
- 例:「重要→主要」ラベル変更、「Qiita記事が TOP に来る」→ UGC 抑制、「無名記事が混ざる」→ はてブ閾値導入
- **教訓**: 綿密な事前設計より、まず動かしてから整える方が早い（ただしブランド遵守など基本ルールは事前に固める）

### 📸 学び 3: スクリーンショット検証は必須
- Playwright で実機レンダリングをキャプチャして目視確認しないと、CSS で想定外の崩れが起きる
- 実例: exec-box の `overflow: hidden` が TODAY'S BRIEFING ラベルを切ってた
- 実例: タブレット幅 (820px) で 1列になっていた → 2列に修正
- **習慣化**: 大きな UI 変更の後は必ず `screenshot-desktop / mobile / tablet` を撮る

### 🤖 学び 4: AI 監査結果を鵜呑みにしない
- 最後の監査で agent が **P0 扱いのメモリリーク**（rewireMore/renderMore）を報告
- 検証: `cloneNode(true)` はリスナーを複製せず、`innerHTML = ...` は古い子を detach → GC するので実害なし
- また別の agent は「LIVE バッジが 12h で消えない」と報告 → 実際は実装済み（agent が該当コードを見落とした）
- **教訓**: AI のレポートも 1 次情報として扱い、必ず自分でコード検証する

### 📦 学び 5: 品質ゲートは自動化
- 一度書いた Playwright テスト 18 件が毎回 regression を防いでくれる
- `ai-news_onboarded_v3` キーの変更でテストが落ちて発見、のような地味な検証にも効く
- **次の展開**: GitHub Actions で PR ごとにテスト実行すれば、マージ前に崩れを止められる

### 🎨 学び 6: ブランド遵守は「制約」ではなく「加速器」
- 5色（Navy / Gold / Cyan / Black / White）しか使えない → 配色で悩む時間がゼロ
- 長方形に border-radius 禁止 → 「角丸にするか四角か」の無限判断が消える
- 結果として**デザイン決定が早く・一貫性が担保**される
- **教訓**: 厳密なルールはクリエイティブを殺すのでなく、創造の速度を上げる

### 🧠 学び 7: 「質」を数値で定義する
- 「バズってる記事」を感覚でなく `likes + retweets×3 >= 3000` で定義した
- 「主要ニュース」を「大手メディア × はてブ >=10」で定義した
- 「新着」を「< 3h」で定義した
- **教訓**: 曖昧な品質基準を数値化すると、議論が短くなり、テスト可能になる

## 5. 再現可能なレシピ

誰でも同じ品質のアプリを作れる最小テンプレ:

```
project/
├── CLAUDE.md           # AI への開発ルール（スペック駆動、1ファイルずつ、WHAT'S NEW 必須）
├── .claude/rules/
│   └── design-rules.md # ブランドカラー/形状ルール（機械可読）
├── apps/xxx/
│   ├── index.html      # Onboarding config / OGP meta / manifest
│   ├── app.js          # 状態・描画・イベント
│   ├── scraper.py      # データ収集（Python 標準ライブラリのみ）
│   ├── sw.js           # PWA Service Worker
│   └── data/           # news.json / archives/ / audio/
├── tests/xxx.spec.js   # Playwright 自動テスト
├── api/xxx-api.js      # Vercel Serverless（Claude / OpenAI API）
└── .github/workflows/
    ├── xxx-collect.yml # 毎朝 scraper + TTS 生成
    └── auto-merge-claude.yml # claude/** ブランチ自動マージ
```

このレシピで Marketing 系の業務アプリは**1日〜1週間で作れる**ことが実証できた。
